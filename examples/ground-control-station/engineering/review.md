# Worked GCS engineering review

Run make review-verify. The [native workflow](../../../scripts/check-review-workflow.py)
retains source, compiled revisions, native resources, trust selection and generated
JSON/Markdown under build/gcs-review. Report data is reconstructed under a second
root and compared with the original. Evaluation time is explicit:
2026-09-08T12:00:00Z, with synthetic reviewer keys generated by the fixture.

The review answers these concrete questions:

- CTRL-FRESH is owned by software, with source-linked hazard and verification
  obligations.
- EXEC-STARTUP records the exact observed build and selects the combined-fault run
  RUN-PROC-COMBINED-nominal for RC-INITIAL. This is bounded simulation plus authored
  operational assertions, not execution of the actual server/aircraft.
- Replacing the host with PART-HOST-2 at an assumed 200 W leaves the retained budget
  stale. Explicitly recalculating with that replacement fails CHECK-POWER and
  CHECK-RUNTIME, while the old equipment/datasheet reviews remain stale.
- Failed upgrade and anomaly candidates retain the owning operations blockers.
  Baseline and PLAN-STARTUP filters narrow operational records without hiding shared
  engineering context or inventing current readiness from old selected evidence.

The workflow compares budget and operations report objects with their native CLI
results. It verifies source-linked control ownership, exact build/run selection,
substitution paths and staleness, recalculation failure, unsupported-domain coverage,
invalid filters and missing native resources. Human engineering source removal
preserves report data and identifies unavailable navigation; explicitly retained
configuration source resources remain required bytes.

The report composes existing domain meanings. It neither signs an approval nor
infers deployment permission, field observations, quantitative safety claims or
hardware qualification from a synthetic passing scenario. Each result retains
authorization: none.
